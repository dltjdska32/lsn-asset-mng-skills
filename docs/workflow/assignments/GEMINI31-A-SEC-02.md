# GEMINI31-A-SEC-02 — SEC parser 검증 실패 회송

Gemini 3.1 Pro High A. 같은 A worktree/대화, 현재 HEAD `65388c1a8b2813982c52148d52cb2b069924a05e`와 SEC-01 미커밋 파일 기준. R02–04 / DESIGN-v0.1. 소유는 `providers/adapters.py`, `tests/unit/test_r04_sec_companyfacts.py`, `handoffs/GEMINI31-A-SEC-02.md`만. file tools only; RunCommand/shell/git/tests/pip/web 금지. 총괄 직접 SEC-01 새 테스트+기존 provider 10개를 실행했으며 2 FAIL: `test_parse_multiple_facts_and_units`은 기대 shares가 첫 관측인데 실제 eps; 기존 `test_sec_companyfacts_is_keyless_and_normalized`는 빈 태그 AVAILABLE을 기대하며 요구사항과 충돌(이 테스트는 총괄이 갱신). 새 테스트는 실제 parser 순서와 일치하도록 고치고 순열 불변성 검증도 추가하라.

코드 안전 문제도 고쳐라: (1) 현재 `_SEC_SUPPORTED_TAGS` + unit whitelist 조합이 revenue/shares, EPS/USD, shares/USD 같은 잘못된 차원도 승인한다. metric별 허용 unit을 정확히 제한하고 `dei`는 주식수 태그만 허용한다. (2) `val in {"NaN", ...}` 는 val이 list/dict일 때 TypeError다. malformed val은 예외 없이 제외한다. (3) `analysis_as_of`가 timezone 없는 datetime이면 aware filed_dt 비교 TypeError다. UTC offset이 있는 시각만 수용하거나 명확히 timezone 적용한다. (4) 원본 fact[] 순서를 바꾸면 반환 순서도 바뀌므로 전체 관측 정렬키(namespace/tag/unit/period/accession/filed/value)를 사용해 결정적으로 반환하라. (5) duration metric은 start/end 유효일과 역순 차단; instant metric은 start 없음을 허용한다. 잘못된 날짜, unsupported form/공시 없는 값은 계산 후보로 승인하지 말라. (6) 잘못된 currency/scale을 암묵적으로 통과시키지 말라. 수정과 반례 synthetic tests 및 남은 실제 deep_research 소비 미완을 인계에 기록하라. 이전 SEC-01의 provider SUCCESS는 코드·테스트 품질 통과가 아니다.
