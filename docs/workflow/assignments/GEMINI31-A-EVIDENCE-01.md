# GEMINI31-A-EVIDENCE-01 — 선택된 가격과 SEC Decimal 저장 경계

Gemini 3.1 Pro High A, A HEAD `9f5f2b5` (R05 structured fallback checkpoint). R01/R04/R05, DESIGN-v0.1. 소유 `runtime/investment_stack/evidence/research.py`, 신규 `tests/unit/test_r04_decimal_evidence.py` 및 `tests/unit/test_r05_price_evidence.py`, `docs/workflow/handoffs/GEMINI31-A-EVIDENCE-01.md`만. 다른 파일 수정 금지. 파일 도구만, RunCommand/shell/git/tests/pip/web 금지.

총괄 코드 감사에서 두 문제: (1) `persist_and_select`는 `calculation_input_approved`/시각만 확인하고 `current_price` 값의 양수·유한/종목·통화를 거르지 않아, structured fallback이 `selected=None`이라고 판단한 부적격 최신값을 raw `fallback.results`에서 다시 선택할 수 있다. 이 저장 경계는 요청 정보가 없으므로 적어도 `metric == current_price` (또는 명확한 현재가 metric)의 bool/NaN/Infinity/0/음수 값을 **기록은 하되 계산 후보로 선택하지 말라**. `ProviderObservation`의 다른 금융/뉴스 값은 함부로 막지 말고, 알 수 없는 currency/instrument 검증은 Phase4 request 경계 후속으로 기록. (2) SEC parser는 Decimal(value)를 내보내는데 현재 `value = observation.value if isinstance(... str,int,float) else None` 때문에 `financial_observations.value_numeric`이 NULL로 저장된다. finite Decimal은 `str(value)` 같은 exact decimal 문자열로 시장/재무 관측에 넣어 저장·조회 값이 사라지지 않게 하라. SQLite REAL로 강제 float 변환하거나 precision loss를 일으키지 말라. bool/nonfinite는 계산 후보에서 차단. 실제 synthetic RunDatabaseManager로 개인 DB 없이 persist→fetch를 검증하고, 부적격 최신 현재가와 적격 과거가 있을 때 현재가 후보/partial 상태를 확인하라. DB 계약/기존 테스트와 충돌하면 정확히 인계하고 함부로 스키마 수정하지 말라. 이 수직 슬라이스만으로 request-level currency/instrument 및 R05 web retry 완료 주장 금지.
