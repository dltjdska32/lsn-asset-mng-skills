# CONTRACT-FIX-01 — 첫 인수검증 수정

Gemini A 기존 세션의 후속 구현. 기준 commit f1b9caa (총괄이 첫 결과를 코드버전으로 보존함). REQ-v1 / 실행 계약 v0.2, R01–05·07·12·16. 부모 배정의 소유권·금지사항 유지. 추가로 providers/contract_adapters.py 신규 파일 소유를 허용하여 contracts→providers 의존을 제거한다. shell/git/pip 실행 금지, 파일 도구로 수정하며 테스트는 총괄이 직접 실행한다.

총괄 검증: 신규 test_contract 32개 0.384s OK지만 release는 CHANGES_REQUIRED. 반드시 현재 worktree의 docs/workflow/reviews/CONTRACT-01-supervision.md 및 REVIEW-DESIGN-01.md를 읽어 실제 반례와 F01–F07을 해소하라. 두 검토 파일은 총괄이 검토 후 이 작업 폴더에 복사했다. 앞선 외부 원본 폴더 read_file 거부는 이 로컬 사본으로 해결하며 외부 경로를 다시 읽지 않는다. 후자는 별도 Codex가 기준 코드에서 수행한 독립 검토다. 아래 현재 구현 반례는 실제 실행 확인이다.

- decode_envelope(version0.2, kind UNRECOGNIZED, payload {}) ACCEPTED → 닫힌 kind/field/version validation과 모든 domain DTO의 typed encode/decode가 필요. 문자열 bool/int 강제변환 금지. unknown envelope/payload fields·invalid enums·numeric float/bool/nonfinite는 거부. datetime/Decimal/enum/nested tuples를 검증된 타입으로 roundtrip. 참고 구현 이름과 wire version은 기존 0.2를 유지해도 좋으며 저장/package 버전과 구분한다.
- SlotSpec(currency USD, dimension MONEY, target_period_end 2025-12-31).matches_candidate('USD',None,None) returns True → 알려지지 않은 required dimension/period는 mismatch. instrument/purpose/기간 start/end/duration/frequency/accounting/consolidation/adjustment/share/coverage 조건 모두 실제 비교 가능한 API로 검증한다. 부분 metadata는 보존할 수 있지만 적격하다고 하면 안 된다. 잘못된 날짜/enum 차단.
- validate_metadata_update_preservation에서 history entry snapshot_hash를 그대로 두고 payload만 변조하면 ACCEPTED → 일반 update_metadata는 기존 보호 namespace의 내용 전체에 대해 exact equality를 요구하고 변경/append/rewind를 거부하라(허용된 facade만 ledger를 갱신). protected namespace가 최초에 없는 경우도 외부 metadata로 가짜 contract ledger를 주입할 수 없도록 하라. corrupted 저장을 empty로 silently reset 금지. 기존 history/calculations/active pointer의 변경/삭제 모두 차단.

추가 필수 수정:

1. contracts/**는 stdlib와 contracts만 import. adapters를 providers/contract_adapters.py로 이동하고 exports/ProviderObservation wrapper를 순환 import 없이 연결. 깨끗한 process에서 contracts import가 provider 없이 가능해야 한다.
2. persist_contract_snapshot/persist_contract_calculation: run_id 일치, strict revision CAS 및 snapshot selection_version, snapshot/hash 무결성, bound evidence가 같은 run에 실제 존재, observation/calculation refs 일치, calculation이 존재하는 snapshot의 정확한 bound inputs를 사용하는지 검증. project_compatible=False에서도 같은 검증. fabricated/missing/cross-run refs 거부. 과거 snapshot은 immutable, idempotent identical retry 조건 명확화. 일반 metadata update와 연결되는 history 보호. 새 evidence가 필요한 경우 typed payload를 같은 transaction으로 기록할 정식 facade를 구현하거나 이미 고정된 evidence만 받는 명확한 API를 제공. 실패 rollback test. 계약 snapshot 여러 purpose 간 최신 revision/active lookup을 일관되게 처리.
3. PublicAvailability의 EXACT/DATE_INTERVAL/UNKNOWN union strictness: DATE_INTERVAL은 source date/검증된 IANA timezone/local midnight→next midnight DST 경계를 보존·검증하는 생성 helper. 임의 upper-only를 적격 날짜로 쓰지 못하게 한다. EXACT는 source locator와 aware instant; missing/unknown은 관측 보존하되 계산 거부. invalid enum/extra unrelated fields 금지. tests에 date-only before/equal upper/DST/unknown timezone 포함.
4. CalculationRecord result_payload deep immutable copy, canonical hash가 결과 payload/unit/currency/모든 의미 필드를 포함. UNAVAILABLE/FAILED/DISABLED는 숫자 결과 null, 승인되지 않은 investment policy를 CONDITIONAL로 우회 금지. 별도 GateDecision purpose/policy version/hash/approval/validation/prerequisites/reasons가 필요. 명시 가정 조건부 계산과 미승인 매매정책을 구분. Bool만 외부에서 넘겨 승인된 사실로 취급하지 않는 타입/검증 경계. FinancialFact/Bar/13F nested roundtrip/hash/tamper 테스트.
5. dict/list가 frozen DTO 안에서 바뀌지 않도록 deep freezing 또는 불변 canonical value를 사용. content hash 결정론: set 허용 시 정렬하거나 거부, non-string mapping key collision 차단, json allow_nan=False. snapshot identity hash와 run-local ID를 제외한 semantic hash를 구분해 permutation/batch 불변성의 도구 제공. hash를 가지고 있다고 잘못된 DTO를 유효하게 판단하지 않는다.
6. 공통 SelectionRequest/CoverageDecision/Protocol 등은 후속 A/B/C가 일관된 실제 API로 쓸 최소 범위로 확정한다. F08 개인 read adapter·7mode는 통합 단계이고 지금 완전 구현할 필요 없다. F01–F07 공통 부분은 출시 전 완성한다. 금융정책 숫자를 발명하지 않는다.

현재 자신의 신규 tests도 실제 계약에 맞게 강화하되 오류를 수용하도록 기대값을 약화하지 않는다. 신규 테스트는 기존 32통과에 더해 위 actual 반례 3개와 cross-run/missing evidence·currency/result tamper·typed DTO 왕복·unknown enum/extra field·gate propagation·namespace injection·rollback을 assert한다. docs/workflow/handoffs/CONTRACT-FIX-01.md에 수정 API/실제 미실행 테스트/남은 이슈를 기록하고 종료. B/C는 아직 시작되지 않았으므로 필요한 common API 변경은 지금 확정 가능하다. 전역 권한/개인DB/기존 migration 변경 금지.
