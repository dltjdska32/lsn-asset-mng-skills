# CLOSE-A handoff

- Scope: R01/R09/R11/D12 market and valuation inputs, based on design baseline abceb4ca7218f166d92b65e677655d1f8f84d807.
- Owned files: runtime/investment_stack/decisions/policy_b_market.py, runtime/investment_stack/deep_research.py, runtime/investment_stack/asset_analysis.py, runtime/investment_stack/calculations/valuation.py, tests/decisions/test_policy_b_market.py, this handoff.
- Quote adapter: read-only run.db binding to one selected same-run market evidence row, matching market observation, pinned as-of, and unique freshness assessment. It checks identity, currency, supported per-share unit, positive finite exact value equality, eligible freshness and nonfuture timestamps. LAST_VALID_CLOSE additionally needs persisted calendar/session fields and matching session date.
- DCF input contract: each base and optimistic scenario must bind all seven values (starting_fcf, annual_growth_rate, discount_rate, terminal_growth_rate, years, net_debt, shares_outstanding) to distinct selected same-run assumption evidence rows. Each row must use the scenario/parameter metric key, exact JSON Decimal value, expected unit/currency, source URI/name, and published/retrieved timestamps at or before pinned analysis as-of. Deep Research excludes scenarios that fail any check. Phase 5 persists the verified values and evidence IDs in both calculation inputs and result metadata.
- DCF output adapter: rereads the persisted calculation and evidence, requires one unambiguous same-run instrument valuation, identical input/result binding records, no duplicate/conflicting selected rows, all seven values for base and optimistic, matching metric evidence IDs, and independently recomputes each per-share DCF value. Only then does it return verified fair-value Money. Scenario IDs or calculation labels alone do not qualify.
- Tests cover valid quote and full value-bound DCF, stale/future/forged quote, last-close proof and rejection, DCF-only scenario ID, plus forged DCF assumption/output values, missing/duplicate bindings, and future assumption evidence.
- Validation: repository .venv with PYTHONPATH=runtime ran the adapter, valuation unit, selected-asset research, Phase 5 runtime, and live deep-research suites successfully (41 tests); compileall for the four changed runtime modules passed; git diff --check passed.
- Remaining provenance decision: run.db has no typed, signed source-receipt contract. This implementation requires an assumption evidence row with exact value, source URI/name and timestamps, but cannot prove the captured source content at that URI actually supports the value, or that the row was inserted by a trusted source adapter. Until the system defines trusted capture/receipt integrity, the adapter should be considered only as strong as those selected persisted evidence records.
- Separate D12 inputs remain outside this adapter: personal state, FX, reserves, costs, risk budget and trade units must be bound by the host before any non-WAIT policy output.
