# CLOSE-A handoff

- Scope: R01/R09/R11/D12 market and valuation inputs, baseline abceb4ca7218f166d92b65e677655d1f8f84d807.
- Owned files: policy_b_market.py, deep_research.py, asset_analysis.py, calculations/valuation.py, test_policy_b_market.py, this handoff.
- Quote bridge independently reassesses persisted FRESH/DELAYED age and LAST_VALID_CLOSE session state. For a last close it requires exchange identity, supported pinned calendar ID, exact scheduled session close, publication by cutoff, and equality with the latest completed session. It also requires evidence and market observation instrument IDs, units, currency, provider IDs and values to match exactly. Evidence observed_at, market observation observed_at and claimed_market_time must identify the same instant. A claimed fresh label cannot override stale timestamps.
- Receipt rule: the current supported market quote adapters populate a source name, provider ID and HTTPS source URL; all are required and must be consistent between the evidence and market observation. A future official adapter that cannot provide a URL needs an explicit trusted provider receipt contract before this path can accept its quotes.
- Weekend behavior: the pinned Nasdaq schedule validates Friday Sep 25 close at 20:00 UTC as the latest completed session at Sunday Sep 27 16:00 UTC. The adapter rejects a Sep 28 11:00 UTC quote labeled as a last close because that timestamp precedes the Sep 28 session open and does not match its scheduled close.
- DCF calculation records bind each base/optimistic parameter to distinct selected, same-run assumption rows, exact values, units/currency, source locator and pinned-cutoff timestamps; calculation inputs/results must carry identical bindings and math is recomputed. However, source URI/name and self-authored value rows do not prove that the source content supports the value. Therefore the adapter now always leaves fair_value_per_share and optimistic_fair_value_per_share unset until a trusted, independently verifiable source-content receipt contract is implemented. Caller IDs, persisted calculation IDs/math, and URLs alone cannot certify fair value.
- Tests cover valid current quote, stale-labeled timestamps, mismatched observed/claimed times, provider/source receipt mismatches or omission, instrument/unit mismatches, forged close calendar IDs, pre-open mislabeled close, valid weekend close, stale/future/forged quote, and DCF self-authored/missing/duplicate/future value cases.
