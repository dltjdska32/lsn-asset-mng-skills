# D12-B policy evaluator handoff

## Scope

Implemented the pure, deterministic D12 option B policy evaluator in
`runtime/investment_stack/decisions/policy_b.py`, with focused tests in
`tests/decisions/test_policy_b.py`. No shared files were changed.

## Public API

`evaluate_policy_b(PolicyBInput) -> PolicyBResult`. Money values include amount,
currency, and a verified flag. `PolicyBInput` accepts missing fields so a
verified base fair value can still produce non-executable reference price tiers
at 80%, 75%, and 70%. Missing personal state, quote, optimistic value, or thesis
status produces `WAIT` and no add budget. Entry tiers state an equal one-third
budget allocation only when all prerequisites are verified. No order/ledger
operation exists; `orders_posted` is always false. An approval reference string
is deliberately not accepted as authorization.

## Policy behavior

- Cash floor: 10% of verified valued investable portfolio (the supplied cash
  must already exclude emergency/planned reserves); available add budget is
  max(cash minus this floor, zero).
- Holding cap: 8% of valued investable portfolio; additions stop at the cap.
- Maximum total add budget is the minimum of cash above floor, cap headroom, and
  an optional stricter verified host risk budget (when supplied); absent a
  separate host budget, the 8% cap headroom itself supplies the policy limit.
  This total is split into three equal Decimal tranches whose final tranche
  absorbs Decimal division residue so the sum never exceeds the total.
- Reduction review triggers at concentration strictly above 10% (8% target),
  quote at or above 1.2x verified optimistic fair value (review a one-third
  fraction), or impaired thesis.
- Inputs are validated for finite, non-negative values, positive per-share
  values/portfolio value, verified status, and matching currency. Missing
  thesis status is unavailable and blocks the add budget.
- Entry tiers are policy reference levels only; the API has no executable flag
  or order path. A complete input set yields `CONDITIONAL`, never authorization.
- Concentration/overvaluation reduction triggers and candidate values require
  verified and currency-matched source values. Overvaluation review returns a
  one-third fraction only when a positive holding value and positive, verified
  holding units exist; unit and currency amounts remain unavailable until
  verified lot/disposition/fee data supports a disposable quantity.
- Monetary inputs must be actual `Decimal` instances; strings and floats are
  rejected without coercion. Contradictory holding value above portfolio,
  cash above portfolio, or cash plus holding value above portfolio blocks the
  result and suppresses reduction triggers and candidate fractions.

## Verification

Focused `unittest` coverage passes (19 tests) using the repository `.venv` and
`PYTHONPATH=runtime`: `python -m unittest tests.decisions.test_policy_b -q`.
Coverage includes threshold boundaries, portfolio-based cash floor, optional
stricter risk cap, concentration, equal tranche sum, reduction conditions,
unverified values, contradictory cash/holding inputs, unverified/zero/missing
holdings, strict Decimal types,
thesis impairment, missing/invalid data, currency mismatch, and no posting.

## Integration note

Generic equity mode may provide only the verified Phase 5 base fair value. In
that case the result intentionally exposes reference prices only and remains
`WAIT`; it must not be represented as an executable recommendation. Callers
must independently verify/pin personal state and evidence. The evaluator does
not treat a caller-provided approval reference as authority.

## Review follow-up

Updated the reserve floor to 10% of valued investable portfolio, guarded numeric
reduction outputs on verified matching-currency inputs, made thesis status
explicit, removed executable tier metadata, and changed complete results to
`CONDITIONAL`. The optional host risk budget only tightens the policy-derived
cap. Reduction evaluation reports only the review fraction, never a tradeable
unit quantity. Non-Decimal inputs are rejected; inconsistent holding or cash
or cash-plus-holding values above portfolio suppress numeric reduction
outputs. An overvaluation review fraction requires positive, verified units and
holding value. The focused suite passes
after these corrections.
